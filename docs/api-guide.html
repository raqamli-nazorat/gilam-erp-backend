Gilam sotuvi savdo markazlari uchun ERP tizimining barcha tayyor API endpointlari: nima uchun, qanday so'rov, qanday javob. Har bir bo'lim mustaqil o'qiladi — kerakli joyga chapdagi ro'yxatdan o'ting.

Base URL · /api/v1/ Format · JSON Auth · JWT (Bearer) Til · uz

Kirish

Javob konverti

Har bir javob (xato bo'lsa ham) bitta umumiy o'ramda keladi. Pastdagi barcha "Javob" namunalari data maydonining ichini ko'rsatadi.

Ruxsatlar (permissions)

            
Har resurs uchun Django permission talab qilinadi — GET uchun ham (odatiy DRF'dan farqli). Format: <app>.view_<model> / add_ / change_ / delete_.

            
Ruxsat yo'q foydalanuvchiga 403, token yo'q/yaroqsiz bo'lsa 401 qaytadi.

          

        


        

          
Filter · qidiruv · tartiblash · soft-delete

          
?search= — resursga xos matn maydonlarida (F.I.Sh., nomi va h.k.) qidiradi. ?ordering=maydon yoki ?ordering=-maydon — kamayish uchun oldiga -. UUID/raqam filterlar vergul bilan bir nechta qiymatni qabul qiladi: ?region=uuid1,uuid2.

          
Soft-delete: DELETE obyektni bazadan o'chirmaydi — is_active=false qiladi. Rollar, foydalanuvchilar, davlat/viloyat/tuman uchun o'chirilgan obyekt ro'yxat va retrieve'dan butunlay yo'qoladi (404). Tashkilot va filial uchun esa aksincha — o'chirilgandan keyin ham ro'yxatda status: false bilan ko'rinishda qoladi (kerak bo'lsa ?status=true bilan filtrlang).

Auth
2 endpoint

        
Login va tokenni yangilash. Resurs emas — CRUD'dan ajratilgan, ochiq (token talab qilmaydi).


        

          
Tizimga kirish
POST

          
/api/v1/auth/login/

          
Telefon raqami va parol bilan kiradi, access/refresh token va joriy foydalanuvchi ma'lumotini qaytaradi. Nofaol (is_active=false) foydalanuvchi rad etiladi.

          
Throttle: IP + telefon raqami bo'yicha 5 ta urinish / 15 daqiqa. Chegaradan oshsa 429 va javobda attempts_left, retry_after_seconds qaytadi.

          
So'rov tanasi

          

          
Javob · 200

          

          
Muvaffaqiyatsiz login → 401 ("Berilgan ma'lumotlar bilan faol hisob topilmadi").

        


        

          
Access tokenni yangilash
POST

          
/api/v1/auth/token/refresh/

          
Amaldagi refresh token orqali yangi access token oladi (foydalanuvchini qayta login qildirmasdan).

          
So'rov tanasi

          

          
Javob · 200

          

          
refresh yaroqsiz/muddati tugagan bo'lsa → 401.
